# V3 — Continuous-Action Side-Scrolling Survival

## Context

**Why this change.** V2 closes the on-policy / discrete-action / multi-agent / curriculum-trained MAPPO story on the 13×13 SRPG. The capstone rubric and the syllabus's Week 8 ("Continuous Control: DDPG/TD3/SAC") call for continuous-action work, and the professor's V3 hints (POMDPs, multi-agent adaptation) and the user's brief (infinite scrolling map, simple enemies, agent dies → episode ends) point in the same direction.

**Outcome we want.** A new self-contained module under `v3-continuous-space/` that:
1. Hosts a 3-unit squad in an **infinite, left→right scrolling, chunk-generated** version of the V2 grid world, with simple scripted enemies spawning in new chunks.
2. Replaces the V2 `Discrete(12)` policy interface with a **continuous `Box`** action per unit, while quantizing movement back onto V2 grid directions and keeping V2 combat semantics.
3. Trains a **shared-policy SAC** agent (off-policy, max-entropy — fits Week 8) using **stable-baselines3**, which is already in `pyproject.toml`.
4. Reuses as much of `highground/engine/` as possible (Grid, Terrain, Unit, combat formulas with height/flank, pathfinding) — only the *world container* (chunked + infinite) and the *action layer* (continuous) are new.
5. Documents an algorithm justification (off-policy / continuous-action contrast to V2's on-policy / discrete MAPPO).

**Out of scope (explicitly).** No classical RL additions, no LSTM/recurrent policy, no LLM steering, no V2 changes. Single algorithm. Single env. Ship it.

## Key design decisions

### World model — chunked sliding-window grid (reuses V2 engine)

- **Visible window**: a fixed `(W=24, H=13)` `Grid` instance (V2's `Grid` from `highground/engine/grid.py`).
- **Camera/scroll**: tracks the **squad centroid x-coordinate**. When the centroid passes a threshold (e.g. column index ≥ 12), the world scrolls right: drop the leftmost column, append a freshly generated column on the right.
- **Chunk generator** (`chunk_generator.py`): each new column is a 13-tile vertical strip with procedurally chosen `Terrain` and `elevation` (reuses V2's enums). Difficulty curve: enemy spawn probability and HP scale with total scrolled distance.
- **World coordinates**: each unit/enemy carries an absolute `world_x` (monotonic int). Tile lookups translate `world_x → window_col = world_x − scroll_offset`. A unit whose `window_col < 0` (scrolled off-screen left) is **killed** — this is the "fail/die" mechanism for falling behind, and is the primary continuous "keep moving right" pressure.

### Action space — continuous interface, V2 grid mechanics

- Per unit: `Box(low=-1, high=1, shape=(3,))` = `(vx, vy, attack_intent)`.
- Movement: `(vx, vy)` is quantized into one of V2's 8 grid directions. The env checks the step with `highground.engine.pathfinding.can_step`, charges the destination terrain movement cost, and updates Charger momentum with the V2 rules.
- Attack: if `attack_intent > 0.5`, attempt attack on **nearest enemy within `Unit.range`**. Attack range, `has_attacked`, Charger momentum reset, and damage all use the V2 semantics (`compute_damage` from `highground/engine/combat.py`, including height/flank bonuses).
- Multi-unit step semantics: **3-step micro-tick**. Each Gym `step()` advances *one* unit; after all 3 player units have stepped, enemies all step once. Mirrors V2's MAPPO micro-action rotation, but with a continuous Box action instead of Discrete(12).

### Multi-agent → SB3 single-agent via shared-policy parameter sharing

SB3 SAC is single-agent. Wrap the multi-agent env so:
- Observation includes a small **agent-id one-hot (3 dims)** + per-unit stats + local view of the world.
- Each `step()` from SB3's POV is "the next unit's turn" — the wrapper rotates `current_unit_idx`.
- One replay buffer, one policy, one critic. All 3 units share parameters (matches V2's MAPPO `share_params=True` setup).
- This is **independent SAC with parameter sharing** (well-known multi-agent reduction; same pattern V2 uses for MAPPO actor sharing).

### Observation

Per active unit (single flat float32 vector, fed to a CNN+MLP feature extractor):
- **Spatial block** (CNN-friendly): `(2 channels, H=13, W=24)` = terrain + elevation of the visible window. ~624 floats.
- **Enemy channel**: `(1 channel, 13, 24)` = enemy HP fraction at each tile (0 if no enemy). ~312 floats.
- **Friendly channel**: `(1 channel, 13, 24)` = friendly HP fraction at each tile. ~312 floats.
- **Non-spatial**: active unit's `(world_x_local, y, hp_frac, attack_cd)` + agent-id one-hot (3) + scroll velocity + alive mask of teammates (3). ~12 floats.

→ obs total ≈ **1260 floats**. Spatial part shape `(4, 13, 24)`.

CNN feature extractor in `feature_extractor.py` mirrors V2's `SpatialCnnMlp` — 4→16→32→32 conv stack, flatten, concat non-spatial, MLP. Lifted from `highground/training/cnn_model.py` and adapted for SB3's `BaseFeaturesExtractor` (no BenchMARL wrapping needed).

### Reward shaping

Per-tick scalar (from active-unit perspective; standard multi-agent shared-reward variant):
| Signal | Value | Rationale |
|---|---|---|
| Forward progress | `+0.05 × Δworld_x` of squad centroid (clamped ≥ 0) | Drives the "keep scrolling right" objective |
| Stagnation | `−0.005` per tick | Penalises camping |
| Enemy kill | `+1.0` | Combat incentive |
| Damage dealt | `+0.02 × hp_dealt` | Shaped combat |
| Damage taken | `−0.02 × hp_lost` | Self-preservation |
| Friendly killed (off-screen or HP=0) | `−1.5` | Shared squad penalty |
| All friendlies dead | `−3.0` + episode end | Terminal failure |
| Tick survived after `world_x > 200` | `+0.01` | Small endurance bonus once curriculum target hit |

### V2-inspired curriculum

V3 should not start SAC directly on the full scrolling combat problem. The
implemented training loop borrows V2's drip-feed idea:

1. **Scroll foundation** — no enemies, easier terrain, strong progress reward.
2. **Weak contact** — sparse weak enemies, attack attempt and in-range bonuses.
3. **Approach transfer** — more enemy pressure and V2-style damage/kill/contact
   shaping.
4. **Full pressure** — full generator difficulty with the same shaped objective.

This transfers the successful part of V2: curriculum and reward design. The
V2 `mappo_phase7_policy.pt` weights do not transfer directly because MAPPO's
BenchMARL discrete actor/critic checkpoint is architecturally incompatible with
SB3 SAC's continuous actor/twin-critic checkpoint.

To prevent the learned "escape to the next strip" exploit, scrolling is locked
while any enemy remains alive in the visible 13x13 grid. Scrolling is also
capped so it cannot push any living player unit off-screen. The policy only
earns forward-progress reward when the visible map is clear, and that progress
is measured by the leftmost living squad member rather than the centroid. A
small dense reward fires when a unit reaches new rightward ground on a clear
map, a lag-lock penalty fires when a survivor blocks safe scrolling, and a
no-enemy stillness penalty escalates until the squad advances. The train script
exposes `--progress-reward-scale` and `--kill-reward-scale`;
`run_reward_sweep.py` trains five overnight variants that progressively lower
progress reward and increase kill reward.

### Algorithm — SAC justification (for README)

| Algorithm | Decision for V3 |
|---|---|
| **SAC** | ✓ Chosen. Off-policy, max-entropy, robust under non-stationary multi-agent dynamics (the "other 2 units" change as policy updates). Sample-efficient — important since the procedural env has high variance per episode. Pairs cleanly with parameter sharing across the squad. |
| DDPG | Deterministic, brittle to hyperparams, no entropy term → bad fit for exploration in procedurally generated terrain. |
| TD3 | Twin critics fix overestimation but lacks entropy bonus → less exploratory than SAC for procedural maps. SAC is strictly preferable here. |
| PPO-continuous | On-policy → wastes the rollout each update. We already did on-policy in V2 (MAPPO); SAC gives the **off-policy contrast** the rubric values. |
| TRPO | Same on-policy issue, plus higher implementation cost than PPO with no benefit over SAC for continuous control. |
| Discrete algos (DQN/REINFORCE/A2C/MAPPO) | Not applicable — V3's whole point is continuous actions. |

**Pedagogical pairing.** V2 = on-policy / discrete / multi-agent (MAPPO). V3 = off-policy / continuous / shared-parameter multi-agent (SAC). Clean axis flip → strong narrative for the report.

## Verification (end-to-end test plan)

Run each step in order. Each is fast unless noted.

1. **Tests pass**:
   ```bash
   pytest v3-continuous-space/tests/ -v
   ```
   Asserts env conforms to Gymnasium API, action/observation space shapes, chunk generation determinism with seed, episode termination on squad wipe.

2. **Smoke test (no learning)**:
   ```bash
   python v3-continuous-space/scripts/play_random.py --episodes 3 --render-gif /tmp/v3_random.gif
   ```
   Should produce a watchable GIF of 3 squad units flailing through scrolling terrain. Confirms env steps, rendering, GIF export. Squad should die in <100 ticks under random policy.

3. **Quick training sanity** (~5–10 min on CPU):
   ```bash
   python v3-continuous-space/scripts/train_v3.py --total-timesteps 50000 --quick
   ```
   Look for non-flat ep_rew_mean trend in TB. If reward stays at floor: fix env before scaling up.

4. **Full training run** (~2–4 hours on a single GPU; can run overnight):
   ```bash
   python v3-continuous-space/scripts/train_v3.py --total-timesteps 1000000
   ```
   Saves best checkpoint to `v3-continuous-space/models/sac_best.zip`.

5. **Evaluation + replay**:
   ```bash
   python v3-continuous-space/scripts/eval_v3.py --checkpoint v3-continuous-space/models/sac_best.zip --episodes 10 --render-gif /tmp/v3_trained.gif
   ```
   Prints mean episode length, mean world_x reached, kill/death stats. GIF should clearly show the trained squad surviving longer and engaging enemies.

6. **V2 still works** (regression):
   ```bash
   python scripts/run_analysis.py --episodes 5
   ```
   Confirms V2 paths untouched.
